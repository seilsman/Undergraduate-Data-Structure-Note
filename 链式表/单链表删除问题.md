
# 单链表删除问题系统笔记


# 一、删除操作的本质原理（结构基础）

## 1️⃣ 单链表删除的必要条件

删除结点 `x` 的结构本质：

$x_{pre}->next = x->next$

因此必须满足：

- 能访问到目标结点
- 必须能访问到其前驱结点

> 单链表删除问题的核心不是“找到目标”，  
> 而是“如何稳定维护前驱”。

---

## 2️⃣ 删除的标准三步

```c
pre->next = target->next;   // 断链
free(target);               // 释放
```

工程原则：

* 先断链
* 再释放
* 不丢失指针

---

# 二、模型板块（结构组织方式）

---

## 模型一：当前结点扫描模型（Current Node Scan）

### 核心思想

* 扫描当前数据结点 `cur`
* 同步维护前驱 `pre`
* 删除时依赖 `pre`

### 抽象结构

```c
pre = L;
cur = L->next;

while (cur != NULL)
{
    if (满足删除条件)
    {
        pre->next = cur->next;
        free(cur);
        cur = pre->next;   // 关键：删除后不能直接 cur = cur->next
    }
    else
    {
        pre = cur;
        cur = cur->next;
    }
}
```

### 特点

* 思维直观
* 适合“查找 + 删除”
* 逻辑清晰

---

## 模型二：前驱扫描模型（Predecessor Scan）

### 核心思想

* 扫描的是“当前结点的前驱”
* 比较对象为 `pre->next`

### 抽象结构

```c
pre = L;

while (pre->next != NULL)
{
    if (满足删除条件)
    {
        target = pre->next;
        pre->next = target->next;
        free(target);
    }
    else
    {
        pre = pre->next;
    }
}
```

### 特点

* 删除操作天然安全
* 不容易跳结点
* 更适合连续删除

# 四、常见错误与风险控制

---

## 1️⃣ 模型混用

错误现象：

* 比较用 `cur`
* 删除却用 `pre->next`
* 指针语义不一致

原则：

> 模型选定后，全程保持一致。

---

## 2️⃣ 跳结点错误

错误写法：

```c
pre = pre->next;
cur = cur->next;
```

若删除发生，可能跳过结点。

---

## 3️⃣ 空表与单结点问题

必须考虑：

```c
if (L == NULL || L->next == NULL)
    return;
```

---

## 4️⃣ 释放顺序错误

错误写法：

```c
free(cur);
pre->next = cur->next;   // 非法访问
```

必须先断链，再释放。

---

# 五、复杂度统一分析

一般删除问题：

$$
T(n) = O(n)   \ \ S(n) = O(1)
$$

# 六、模型选择流程图

---

## 文字流程图版本

```
开始
  ↓
是否涉及连续删除？
  ├── 是 → 优先选择「前驱扫描模型」
  │
  └── 否
        ↓
是否以“查找某个结点”为主？
        ├── 是 → 选择「当前结点扫描模型」
        │
        └── 否
              ↓
是否涉及复杂结构控制（如双指针）？
              ├── 是 → 当前扫描 + 快慢指针
              └── 否 → 任一模型均可
```

---

## 核心选择原则总结

* 删除可能连续发生 → 前驱扫描更稳定
* 以查找逻辑为主 → 当前扫描更直观
* 复杂结构问题 → 当前扫描更灵活

---

# 七、结构性认知总结

单链表删除问题的本质是：

> 指针控制流问题，而不是值比较问题。

真正掌握的标志：

1. 看到题目立即选定扫描模型
2. 预判是否会连续删除
3. 明确前驱维护方式
4. 代码结构一次成型
